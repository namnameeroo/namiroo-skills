# wiki-agent

기술 용어 하나를 받아 조사·설명하고, Obsidian vault의 wiki 폴더에 용어 노트로 저장한다.
노트는 두 순간을 동시에 섬긴다 — 만들 때 **깊이 이해**, 나중에 **빠르게 재훑기**.

호출: `/wiki-agent <용어> [주 도메인 맥락(선택)]`
예: `/wiki-agent triage` 또는 `/wiki-agent triage "멀티에이전트"`. 용어가 없으면 한 번 묻는다.

## 1. 설정 로드 (config)

설정 파일: `~/.claude/wiki-agent/config.json`. 매 호출 시작 시 읽는다.

**파일이 없으면 (첫 호출) 인터랙티브 세팅:** 단일 `AskUserQuestion`으로 아래 기본값으로 진행할지 / 수정할지 묻는다.

- **vault_path** — 기본값: `/path/to/Obsidian Vault`
- **wiki_folder** — 기본값: `wiki`
- **persona** — 조사 관점(렌즈) 및 주 도메인 폴백. 기본값: `프론트엔드 개발자. 기술 용어 위주. 어휘의 근원·다양한 도메인 용례·사용 컨텍스트를 알고 싶어함.`
- **format_rules** — 기본값: `정의·어원·도메인별 용례·사용 컨텍스트는 한 줄로 간결히. 핵심 개념·왜 중요한가는 핵심만 불릿 2~4개 또는 3~4문장. 한국어 설명 + 영어 용어 병기. 구체적 예문 포함.`

응답을 받아 `~/.claude/wiki-agent/`를 만들고 `config.json`을 쓴다. `research_mode`는 항상 `light-hybrid` 고정.

이후 다른 용도로 쓰려면 `persona`/`format_rules`만 직접 수정하면 된다.

## 2. 용어 처리 흐름

1. 인자에서 용어를 얻는다. (없으면 한 번 묻는다)
2. **주 도메인 결정** (깊이를 어디에 줄지): ① 호출 시 맥락 인자가 있으면 그것 → ② 없으면 용어의 현대 지배적 용법을 추론 → ③ 그래도 모호하면 `config.persona`의 도메인.
3. **파일명 슬러그**: 표준 영어 용어를 kebab-case로 (`Event Loop` → `event-loop`). 한국어 입력이 영어 표준어에 대응하면 영어 표준어를 정식 명칭으로 쓰고, 한국어 독음은 `aliases`에.
4. 대상 경로: `<vault_path>/<wiki_folder>/<slug>.md`
5. **존재 확인 — 묻지 않는다.** 있으면 본문 재작성(업데이트)하되 기존 `created`는 보존. 없으면 새로 만들고 `created`는 오늘(`date +%F`).
6. 조사 → 작성 → 파일 쓰기 → `_index.md` 갱신 → 보고.

## 3. 조사 (research_mode: light-hybrid)

모델 지식으로 먼저 초안을 만든다. **어원이나 실제 용례가 불확실할 때만** `WebSearch`를 1~2회 사용해 검증한다. 딥 리서치·다중 소스 팬아웃은 하지 않는다.

## 4. 노트 작성

`config.persona`(관점)와 `config.format_rules`(작성 규칙)를 적용한다.

**구조 원칙**: 상위 헤딩은 고정(→ 100개 쌓여도 스캔됨). 깊이는 `핵심 개념`·`왜 중요한가`의 *내용*만 주 도메인에 맞춰 변한다.

템플릿:

```markdown
---
term: <정식 영어 명칭>
aliases: [<한국어 독음/별칭>]
tags: [terminology, <주 도메인>]
created: <YYYY-MM-DD>
---
# <정식 영어 명칭>

## 한 줄 정의
<1~2문장, 한 줄로 간결히>

## 어원 / 근원
<어디서 왔는지 — 짧게 한 줄>

## 핵심 개념
<주 도메인 기준 메커니즘/구성요소. 불릿 2~4개 또는 3~4문장. 깊게.>

## 왜 중요한가
<존재 이유·장점. 불릿 2~4개 또는 3~4문장. 깊게.>

## 도메인별 용례
<주 도메인을 뺀 다른 도메인들을 한 줄씩 survey(넓이). 각 항목: 도메인명 + 짧은 설명 + 예문.>
- **<도메인>**: <설명> — 예: "<예문>"

## 사용 컨텍스트
<언제/왜 쓰는지 — 한 줄>

## 관련 용어
<자연스럽게 연결되는 용어를 [[slug]] 위키링크로. 없으면 섹션 생략.>
```

**넣지 말 것**: 다단계 walkthrough 시나리오, 제품·모델·프레임워크 이름(시점 민감 — 영구 노트의 독), 대화형 마무리 문장("도입 고민중이신가요?" 류). 빈 섹션은 placeholder 없이 통째로 생략한다.

## 5. _index.md (MOC) 갱신

`<vault_path>/<wiki_folder>/_index.md`를 유지한다. 없으면 만든다. 주 도메인 태그별로 그룹핑된 위키링크 목록이며, 이번 용어 줄을 추가(없을 때)하거나 한 줄 요약을 갱신(있을 때)한다.

```markdown
# Wiki Index

## ai-agent
- [[triage]] — 밀려드는 항목을 분석해 우선순위·분배를 정하는 과정
```

## 6. 보고

저장 경로와 한 줄 요약만 보고한다. 전체 노트 본문을 채팅에 다시 출력하지 않는다.
